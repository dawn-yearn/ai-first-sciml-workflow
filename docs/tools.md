# 资料获取、核验与插图处理

工具服务于阅读。优先把一篇代表作完整走通，再批量处理；遇到特殊排版或下载障碍，记录并单独处理。

## 1. 下载：先找到正确版本，再选择获取方式

先用正式题名、作者和 DOI 确认论文，再找期刊开放版本、作者主页、机构库或预印本。记录来源 URL、版本和下载日期。

| 遇到的情况 | 下一步 |
| --- | --- |
| 可直接下载 PDF | 使用普通下载即可，之后做文件核验 |
| 下载结果是 HTML／JS 查看器 | 回到落地页寻找实际 PDF 入口，检查保存内容 |
| 限速或 429 | 降低并发、退避重试，遵守站点提示；也可寻找其他开放版本 |
| 浏览器可访问，脚本失败 | 检查会话、跳转与浏览器下载流程；必要时复用有权访问的浏览器会话 |
| 仍无法获取 | 记录失败来源和原因，先继续其他论文 |

当日实践使用过 Scrapling 的 HTTP 获取与浏览器会话方式。它们属于针对站点的适配，不能把一次成功写成通用保证；403、429 等状态本身也不足以判定具体拦截机制。使用当前版本时查看[项目文档](https://github.com/D4Vinci/Scrapling)。原项目的站点脚本带有固定论文 URL 和本地路径，保留为历史记录，本目录先提供可复用的核验与裁图入口。

## 2. 核验：文件能打开，还要确认下对了论文

从本仓库目录运行，示例路径用自己的文件替换：

```powershell
python tools/verify_pdfs.py "workspace/papers/P001.pdf" --output "workspace/verify-P001.json"
```

支持一次传入多个 PDF。脚本检查文件头、可读取性、页数、文件大小和 SHA-256，并给出首页文字预览；遇到失败返回非零退出码，JSON 中逐个列明状态。

**题名、作者、DOI 与版本仍需对照核实。** `identity_verified` 默认是 `false`。相同哈希能识别完全相同的文件；不同哈希可能只是排版或版本不同，不能自动当作不同论文。

## 3. 转成可搜索文字，同时保留原 PDF

若需要 Markdown，先检查当前选定的 Python 环境中是否已有 MarkItDown。以下命令使用该环境的解释器：

```powershell
python -m markitdown --version
python -m markitdown "workspace/papers/P001.pdf" -o "workspace/papers/P001.md"
```

若项目指定了 Conda 环境等运行方式，应遵循该项目约定。由 AI agent 安装依赖前，先说明所需包、用途、环境与安装命令。转换后检查输出存在且非空。文字适合搜索和辅助阅读，公式、双栏顺序、表格与图意仍回 PDF 核对。[MarkItDown 官方说明](https://github.com/microsoft/markitdown)、[pypdf 关于文字提取的说明](https://pypdf.readthedocs.io/en/stable/user/extract-text.html)。

## 4. 提图：自动生成候选，再检查完整性

论文插图可能由矢量线条、文字和多个图片对象组合而成。将整页渲染后裁剪，能够保留所选区域的整体外观；直接导出某个内嵌图片对象，未必得到完整图。[PyMuPDF 页面渲染与裁剪文档](https://pymupdf.readthedocs.io/en/latest/recipes-images.html)。

自动模式沿用当日脚本：识别 Figure／Fig 等图题，估计栏宽，并向上寻找留白边界。输出是**待检查的候选图**：

```powershell
python tools/extract_figures.py "workspace/papers/P001.pdf" "workspace/figures/P001-candidates"
```

它保留了原来的排版启发式，固定约 216 DPI。55 像素留白阈值依赖这一分辨率；跨栏图、图内大间距、侧边图题、扫描件和段首引用都可能造成误判。图号去重也可能误选首次引用或漏掉续图。**“提取了 N 张”只说明生成了 N 个文件。**

发现裁切错误时，先渲染整页：

```powershell
python tools/extract_figures.py "workspace/papers/P001.pdf" "workspace/figures/P001-page" --page 6
```

查看后指定矩形，示例数值仅用于展示参数，必须按页面调整：

```powershell
python tools/extract_figures.py "workspace/papers/P001.pdf" "workspace/figures/P001-crop" --page 6 --bbox 40 100 550 420
```

页码从 PDF 文件第 1 页计数；矩形为左、上、右、下，使用 PDF 点坐标，原点在页面左上角。普通未旋转页面在 216 DPI 预览中，像素坐标除以 3 可换算为点坐标；旋转或特殊页面应另外核对。输出目录必须新建或为空，脚本不覆盖已有结果。

每次输出包含 `manifest.json`：来源文件名与哈希、PDF 页码、图片文件名、尺寸；手动裁图还记录矩形坐标。检查所有将用于报告的图片：子图是否齐全，坐标、图例、色条和图题是否被截断，是否误带正文，图片是否确实对应所写结论。

## 5. 写笔记与发布前的文件整理

给论文分配稳定编号，图片名保留图号和 PDF 页码，笔记标注出处。存储时使用项目内相对路径，便于迁移；若阅读器只接受绝对图片路径，在该阅读器的展示文件中转换，避免把个人盘符写进通用模板。

链接写好后实际打开检查。含空格的链接可编码为 `%20`；不支持锚点的阅读器，可用论文编号配合查找。未来公开分享图片或全文时，另核对其授权和引用要求，工具仓库不默认打包文献内容。

## 运行条件与验证范围

脚本需要 Python 3.11 或更高版本。`verify_pdfs.py` 使用 pypdf；`extract_figures.py` 使用 PyMuPDF、Pillow、NumPy。依赖列于 [requirements.txt](../requirements.txt)，可复用现有环境，不自动安装。

这两个脚本仅处理本地文件，下载部分提供方法和历史经验。自动裁图不能保证适配所有排版；文字核验不代替论文身份和图意核对。

- 对 Page 2025 的 13 页 PDF 完成核验；假 PDF（HTML）被拒绝，已有输出不会被覆盖，特殊字符可以正常输出。
- 自动模式生成 8 张候选图，但其中“图 3”误取了正文引用，部分图题也未完整保留。因此此模式保留为候选生成工具，不能宣称自动提取已全部正确。
- 对另一篇对流论文的第 28 页指定区域裁图，已目视检查完整子图、坐标和图题；越界坐标被拒绝。
